## Runtime: should `.67` move off Ollama 0.33.3? (checked 2026-09-24)

| Ollama | bundled llama.cpp |
|---|---|
| **0.33.3** (on `.67`), 0.34.0 | b10760 |
| 0.34.2, 0.34.3 | b10969 |
| 0.34.4 (latest, 09-23) | b11081 |

On Linux, 0.33.3 runs every GGUF through the bundled `llama-server` (`llm/llama_server.go`), so
the llama.cpp bump touches every generated token. Tool-call and thinking parsing are Ollama's
own code (`model/parsers`), so llama.cpp's `chat:` fixes (qwen3-coder parsing, gemma4 tool
grammar) **never reach us**.

**What the 321 llama.cpp commits (b10760 → b11081) bring for our models (single GPU, one request):
nothing measurable.**
- Q4_K/Q5_K branchless unpack (#26705): the gain starts at batch ≥ 4–5. We decode at batch 1.
- MoE matmul races (#28475) and the f16 FA barrier (#27870) were found by the CUDA sanitizer and
  never reported as wrong output.
- CUB argsort corruption (#28389) is specific to sm_50 with CCCL 2.x.
- The rest is multi-GPU/TP, MTP drafting, DeepSeek/GLM sparse FA, other backends and CI.

**What matters is on the Ollama side:**
1. **A silent truncation in the runtime we are measuring on** (#18374). In 0.33.3,
   `llama_server.go` ends a completion *as if normal* once the same token (after `TrimSpace`)
   repeats more than 30 times in a row. Before, `return ctx.Err()` (nil); after, the limit is 100
   and the error is real. Qwen tokenises digits one by one, and whitespace-only tokens all trim to
   `""`, so a 32-digit zero pad or a run of blank-line tokens is enough to trigger it. Claude Code
   would see an ordinary end of turn. **Not yet shown to have hit any trial**, but it is the same
   shape as every defect in this project: silent, and indistinguishable from a model result.
2. **Anthropic endpoint thinking mapping changed** (`anthropic/anthropic.go`, with #18473). The
   `output_config.effort` value is now passed through as a model-defined thinking level when the
   model declares levels. That changes what "thinking on" means per model, so the thinking-parity
   arm is **not comparable across the upgrade**.

**Decision:** stay on 0.33.3 for this round, since the runtime is part of the measurement.
Upgrade between rounds for (1). After upgrading, re-run the thinking-parity smoke test and one
reference pass before trusting any number.
