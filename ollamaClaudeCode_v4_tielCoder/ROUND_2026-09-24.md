    and the MTP repo's draft head went from Q8_0 to Q3_K. If our blob predates 09-10 the pick runs
    the old template. Compare digests, re-pull, and re-run gates plus ledger
    ([repo](https://huggingface.co/peculiar-ragdoll/Tiel-Coder-35B-A3B-GGUF-MTP))
  - **The caching fix has a concrete switch: `CLAUDE_CODE_TOTAL_TOKENS_REMINDER=off`.** Measured in
    the issue: 146 turns, 6.5M uncached input tokens and cache_read stuck near 3k; with `off`, caching
    works (`fixed` does not help). Ollama sets it only when it launches Claude Code itself
    ([PR #17918](https://github.com/ollama/ollama/pull/17918), [PR #18465](https://github.com/ollama/ollama/pull/18465)),
    not in our `ANTHROPIC_BASE_URL` setup. Undocumented by Anthropic
  - **gemma4 handicaps our numbers do not show**: Ollama's gemma4 renderer drops tool parameters named
    `description` or `type`, and Claude Code's Bash tool has `description`
    ([PR #18503](https://github.com/ollama/ollama/pull/18503), open). Its tool-calling KL under q8_0 KV is
    0.569, against 0.040 for Qwen3.6 ([localbench](https://localbench.substack.com/p/kv-cache-quantization-benchmark)),
    so gemma4 must stay on f16 KV
  - expected, not a fault: llama-server busy-waits 10–20 CPU cores on hybrid models since 0.32.14 even at
    100% GPU ([PR #18613](https://github.com/ollama/ollama/pull/18613))
  - **Prefix caching is broken by Claude Code itself**: Ollama hoists the per-turn `<total_tokens>`
    reminder into the system block, so the cached prefix never stabilises and input grows every
    turn ([ollama#18431](https://github.com/ollama/ollama/issues/18431), open). The reported workaround
    of suppressing that reminder recovered near-zero fresh input. **Largest potential speed win.
    Measure it first.**
  - **Penalties may be no-ops on qwen35moe**: the Go engine does not implement penalty sampling
    ([ollama#14493](https://github.com/ollama/ollama/issues/14493), open). This conflicts with our v4
    finding that presence_penalty 1.5 cost 41–52%. Re-test to see which holds on 0.33.3
  - `keep_alive -1` (no 5-min unload), and `CLAUDE_CODE_AUTO_COMPACT_WINDOW` set below 262k,
    because Claude Code assumes hosted windows. `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`.
    `ANTHROPIC_SMALL_FAST_MODEL` = the same local tag
  - KV cache `q8_0` is low-risk and would free VRAM for a bigger quant. `q4_0` degrades long-context
    recall. Measure with the needle gates
  - **Not worth it:** MTP/speculative decoding on CUDA. Ollama gates it to MLX, and a controlled
    RTX 3090 run on this exact model measured a net loss in every spec-decode mode
    ([writeup](https://hackmd.io/ODXuOQNzSiyUITz7g9mtBw), [llama.cpp#24670](https://github.com/ggml-org/llama.cpp/issues/24670))
  - open: tool-call arguments do not stream incrementally, so a long diff can hit Claude Code's
    ~255 s timeout ([ollama#14858](https://github.com/ollama/ollama/issues/14858))

## Runtime: should `.67` move off Ollama 0.33.3? (checked 2026-09-24)

| Ollama | bundled llama.cpp |
|---|---|
| **0.33.3** (on `.67`), 0.34.0 | b10760 |
| 0.34.2, 0.34.3 | b10969 |
| 0.34.4 (latest, 09-23) | b11081 |

On Linux, 0.33.3 runs every GGUF through the bundled `llama-server` (`llm/llama_server.go`), so
the llama.cpp bump touches every generated token. Tool-call and thinking parsing are Ollama's
own code (`model/parsers`), so llama.cpp's `chat:` fixes (qwen3-coder parsing, gemma4 tool
grammar) **never reach us**.

**What the 321 llama.cpp commits (b10760 → b11081) bring for our models (single GPU, one request):
nothing measurable.**
- Q4_K/Q5_K branchless unpack (#26705): the gain starts at batch ≥ 4–5. We decode at batch 1.
- MoE matmul races (#28475) and the f16 FA barrier (#27870) were found by the CUDA sanitizer and
  never reported as wrong output.
- CUB argsort corruption (#28389) is specific to sm_50 with CCCL 2.x.
- The rest is multi-GPU/TP, MTP drafting, DeepSeek/GLM sparse FA, other backends and CI.

**What matters is on the Ollama side:**
1. **A silent truncation in the runtime we are measuring on** (#18374). In 0.33.3,
   `llama_server.go` ends a completion *as if normal* once the same token (after `TrimSpace`)
   repeats more than 30 times in a row. Before, `return ctx.Err()` (nil); after, the limit is 100
   and the error is real. Qwen tokenises digits one by one, and whitespace-only tokens all trim to
   `""`, so a 32-digit zero pad or a run of blank-line tokens is enough to trigger it. Claude Code
   would see an ordinary end of turn. **Not yet shown to have hit any trial**, but it is the same
   shape as every defect in this project: silent, and indistinguishable from a model result.
2. **Anthropic endpoint thinking mapping changed** (`anthropic/anthropic.go`, with #18473). The
   `output_config.effort` value is now passed through as a model-defined thinking level when the
   model declares levels. That changes what "thinking on" means per model, so the thinking-parity
   arm is **not comparable across the upgrade**.

**Decision:** stay on 0.33.3 for this round, since the runtime is part of the measurement.
Upgrade between rounds for (1). After upgrading, re-run the thinking-parity smoke test and one
reference pass before trusting any number.
