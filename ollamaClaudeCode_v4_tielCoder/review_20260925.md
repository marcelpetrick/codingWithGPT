```
#1  HIGH  Architecture  (design: the speed axis)
    The pick rests on session speed (KAT 46 s vs Tiel 83 s), but every reference ledger session ran on
    Claude Code 2.1.274 (09-17) and every candidate on 2.1.282 (09-25). Verified from
    `claude_code_version` in results/cc/*-hard-thinkon-r1.jsonl, and cc-session.tsv records no version.
    ByteShape, which is qwen3.6's own weights, needs 13 turns where qwen3.6 needed 18-19, so the client
    moves the number. Re-run every contender on one version before the speed verdict stands.
    STATUS: scheduled. s12-rebaseline.sh (3022477) runs ledger x5 for all six contenders on 2.1.282,
    back to back. The KAT verdict is provisional until it reports.

#2  HIGH  Code  s10-one.sh:25
    The scripts that share the one-model box coordinate only by pgrep polling, and the run-all clause
    `! grep -q '5/7' results/run-all.log` matches a stale line: the log is append-only and already
    holds "5/7" from 09-24 16:52. So s10-one never waits for a later run-all, and run-all.sh:25 waits
    only for GO_official_tb. The documented restart launches both at once, which puts two models on
    the box and gets the candidate cut and deleted as a "spill". Use one flock on a box lock held by
    every script for its whole run.
    STATUS: open. Mitigated today by running everything as ONE sequential chain (chain-0925).

#3  HIGH  Code  s9-candidates.sh:163
    If the /api/ps read fails (timeout, link drop), RES and VRAM are empty, the "not loaded" test
    passes, `fit "" ""` returns FAIL, and G1 books "CUT-G1 spilled" and DELETES the ~24 GB source
    pull. That is the 09-24 16:51 failure one step later. A non-numeric read must stop the screen
    with nothing recorded and nothing deleted.
    STATUS: fixed in 418bf79.

#4  HIGH  Architecture  README.md:28
    "each ran at its vendor sampler" is false. The qwen3.6 reference ran greedy (t 0), the candidates
    at t 0.6, and KAT at t 1.0. "qwen3.6 can be replaced" and "the qwen3.6 family leaves held-out
    tests failing" rest on greedy qwen3.6. The t06 control runs Terminal-Bench only, with no ledger.
    Correct the sentence, and add a ledger run for qwen3.6 at its vendor sampler.
    STATUS: document fixed in b684356 (README) and 1e29054 (round). The t06 ledger x5 is in s12.

#5  MEDIUM  Architecture  ROUND_2026-09-24.md (plan: "How a candidate takes the pick")
    "Clearly faster session" had no number, and the rule text first appears in bb21bc1 (09-24 14:22),
    after the reference results (3a5262c, 14:06): it was fixed before the candidates, not before all
    results. With no number, a close call can be decided either way. Write the threshold down.
    STATUS: fixed before any new data, in the s12-rebaseline.sh header (3022477): median >= 25% lower
    AND non-overlapping 5-run ranges; quality = median 18/18 and no run below 16.

#6  MEDIUM  Architecture  (design: evidence standards)
    Terminal-Bench (27 trials) is declared to "separate nobody", yet the quality axis "separates" on
    3 runs. KAT 3/3 at 18/18 vs ByteShape 1/3 has a Fisher exact p of about 0.4. So the rule in
    practice reduces to "18/18 x3 + faster". Hold both axes to one standard.
    STATUS: partly addressed. The ledger goes to n=5 in s12, and s11-ext.sh settles correctness for
    the top two with a paired per-task sign test over ~39 tasks, with the rule fixed in advance.

#7  MEDIUM  Code  terminalbench/official/summarise.py:181
    The column printed as `median_s` is `a["sec"] / a["n"]`, a MEAN that includes agent timeouts. It
    rewards a model that fails fast. "KAT: fastest Terminal-Bench median (126 s)" is a mean; the real
    medians are ByteShape 47 s, KAT 55 s, Tiel 65 s. Rename the column or compute the median.
    STATUS: fixed. The column is labelled mean_s (e2e3cf9), and the claims are corrected with true
    medians (1e29054, b684356).

#8  MEDIUM  Code  make-dashboard.py:90
    tokrate() takes the median over ALL rows of a model, but tokrate.tsv has one row per prompt size
    (0, 2,000, 20,000 words). The dashboard therefore shows the 0-word value (qwen3.6 124, where 2k is
    131.6), contradicting its own tooltip ("at a 2,000-word prompt"). The ROUND tables mix sizes the
    same way: KAT "118 (2k)" is set beside Tiel "107" and qwen3.6 "124", both 0-word values.
    STATUS: fixed in e2e3cf9 (filter prompt_words == 2000). The ROUND tables are corrected in 1e29054.

#9  MEDIUM  Code  cc-session.sh:76
    CC_ARM labelled only the transcript file, not the TSV row. Every reader (s9-parse.py ledger(),
    make-dashboard.py ledger()) pools all rows of a tag, so refine-ab's R1 sessions would have mixed
    into KAT's session time and held-out scores.
    STATUS: fixed. 418bf79 and 3022477 give each arm its own TSV (cc-session-<arm>.tsv).

#10  MEDIUM  Architecture  CANDIDATE_REGISTER.md (Laguna row) / s9-candidates.sh (G2)
    G2 was applied unevenly. occamy and Ornith-1.5 failed T5 (nested schema) and were screened in,
    with the 8x re-run deferred. Laguna was cut on a v3 8/10 result at the GGUF-default sampler,
    two minutes after its vendor sampler had been added (706cffd -> a19ecb0), and never re-gated.
    Apply one rule to all.
    STATUS: scheduled. s12 runs T5 x8 for all five screened models and re-gates Laguna under the
    current setup (its GGUF was re-pulled today).
```
