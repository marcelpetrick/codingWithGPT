# Cleanup of `.67`, 2026-09-18 — what was deleted, and how to put it back

Companion to `measurements.md` §19 and `results/inventory-67.txt`. Run over the Ollama HTTP
API (`DELETE /api/delete`); there is no SSH to `.67`, so this is the only route.

**15 tags across 6 whole weight blobs. 132.89 GiB (142.7 GB) freed — 48% of the store.**
274.78 GiB / 33 tags / 13 blobs  ->  141.89 GiB / 18 tags / 7 blobs.

Every family was removed **whole**. That is the point: a derived tag shares its parent's blob,
so deleting one and keeping a sibling frees nothing — v3 §11a proved that by freeing 0.00 GiB
across five deletions. All six blobs here released.

`/api/ps` was checked before each pass. Only `north-mini-code-1.0:q4_K_M-ctx256k-agentic` was
ever resident, and it is a keeper; nothing was evicted from under a session.

## Rebuilding any of them

Bases come back with `ollama pull <tag>`; `hf.co/peculiar-ragdoll/Cyber-Tiel-Coder-35B-A3B-GGUF:UD-Q5_K_XL`
is a direct pull too. Derived tags are recreated with the recipe in `README.md` §4, substituting
the parameters recorded below. `qwen3-vl:32b-ctx49k` is the easiest: its Modelfile is still in
the repo at `../ollamaClaude_ImageProcessing/Modelfile-qwen3-vl-32b-ctx49k`.

Note `presence_penalty 1.5` on the stock `qwen3.6` tags — the Qwen vendor default that cost
~35% of generation speed in v1. The `-agentic` variants set it to 0. Do not restore the stock
value into a tag you intend to drive Claude Code with.
