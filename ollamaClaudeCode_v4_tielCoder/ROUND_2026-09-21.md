## The four defects

### 1. One repo, two answers to "which model is the default"

`README.md` (09-17) said Tiel displaced north-mini. `BENCHMARK_HARNESS.md` §9a (09-18) said
qwen3.6 was slot 1. The first rests on the ledger fixture, which **was** at thinking parity
(verified per run from `think_chars`, not from the config) and survives. The second rests on a
Terminal-Bench round that is void. Both are now labelled provisional, and the README says which
evidence each rests on. Fixed before any model was loaded.

### 2. The arm was not in the data

The parity run would have written its rows into the same TSV as the round it replaces, under the
same model names, and the two would have pooled into one rate with nothing saying so — the
original defect wearing different clothes. Run-ids now carry `-thinkon`/`-thinkoff`,
`summarise.py` rolls up per arm, `make-report.py` renders exactly one. Verified byte-identical
output on the existing data before trusting it.

### 3. A partial pass is not a rate — mine

`summarise.py` printed a rate for a qwen3.6 n=2 pass holding **3 of 20 trials**. The two it had
were `git-multibranch` and `polyglot-c-py`, the two hardest tasks in the subset, so the control
appeared to collapse to 33%. That number was in the table I was about to hand over.

The cause is that the upstream harness writes run-level `results.json` from the **first** finished
trial and appends, and `tb.lock` lives for the whole run — so a cut-short pass is byte-for-byte
the shape of a finished one. My own resume check trusted that file, which would have skipped an
interrupted pass as "done". Completeness is now trial directories counted against tasks ×
attempts, everywhere.

### 4. The sampler was never at parity either

`/api/show` on the standing four: **temperature 0** (qwen3.6), 1.0 (north-mini), 1.0 (gemma4),
0.6 (tiel-coder). Three sit exactly on their vendor's recommendation. The control does not, and
it is running greedy.

Proven on the wire rather than assumed, on `.37` so the round was untouched: a baked temperature
applies when the client sends none (3/3 identical); a client-set one overrides it (3/3
different); and **Claude Code sends none** — a temp-0 tag answered identically 3/3 through the
real CLI, a temp-1.8 tag differently 3/3. So the baked value is what four rounds of benchmarks
actually ran at.

It costs a headline: round 1's *"qwen3.6 is dramatically more reproducible — 1 flipping task
against 3–4"* is what greedy decoding does. That is the sampler, not the model, and it was the
second pillar under slot 1.

## Decisions

| decision | why |
|---|---|
| **The subset is not touched** — `conda-env-conflict-resolution` stays unpromoted, 10 run, 9 scored | ~11% granularity against a validation cycle, a subset change and comparability with round 1, while confounding the one variable the re-run isolates |
| **The round in flight was not stopped** when the sampling defect was found | its other three models are at vendor spec, and it is the first thinking-parity arm this project has. The control is re-run at spec afterwards instead |
| **The test group is nine candidates, screened not benchmarked** | a screen is minutes, a Terminal-Bench pass is 1.5 h. Only survivors meet the standing four (§9a intact) |
| **Qwen3.6-27B dense removed** | the dense shape does not earn a slot here; the A3B coder on the same base answers the same question without the 4× handicap |
| **`.67` only** | `.37` is a different VRAM budget and a different runtime; a number from it is not comparable. Used once today for an API probe that needed a server the round was *not* using |
| **Overlapping intervals are "not separated"** | 9 scored tasks × n=3 is ±19 points. Fixed before the results, so they cannot pick the rule |
