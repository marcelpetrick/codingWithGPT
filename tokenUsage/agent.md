# How the token-usage report is computed

This repository produces two deliberately different views of local Claude Code
and Codex usage. They must not be mixed without keeping their labels because
the underlying applications retain and deduplicate history differently.

## Publishable retained-total report

The LinkedIn report is generated by `render-linkedin.py`. It reads only local
usage metadata; it does not read source files or upload prompts.

### Claude Code annual total

Source: `~/.claude/stats-cache.json`.

For every entry in `modelUsage`, the report computes:

```text
inputTokens
+ outputTokens
+ cacheReadInputTokens
+ cacheCreationInputTokens
```

The sum across all models is the retained Claude Code headline. “Claude Code”
means the tool that recorded the session, so this total can include local or
third-party models routed through Claude Code, not only Anthropic models.

Claude monthly bars use `dailyModelTokens`, grouped by the `YYYY-MM` portion of
each date. On the 2026 snapshot, daily token history exists only from July 5
through August 27, while `modelUsage` begins with sessions from May 3; therefore
the annual total is more complete than the monthly series.

The report calculates the unallocated Claude amount as:

```text
Claude annual modelUsage total - sum(dailyModelTokens)
```

That amount is called out explicitly and is not invented or distributed over
May, June, or early July. May and June are shown with stripes rather than zero
bars, and July/August are described as partial reporting periods.

### Codex annual and monthly totals

Source: `~/.codex/state_5.sqlite`, table `threads`.

The annual headline is `SUM(tokens_used)` for threads whose `created_at` falls
inside the selected UTC calendar year. Monthly bars group the same values by
`strftime('%m', created_at, 'unixepoch')`; consequently, the full retained
total of a thread is assigned to the month when that thread began, even if the
thread was used again later.

### Combined annual total

```text
retained Claude Code total + retained Codex total
```

These are raw tokens and include cached context. They are not API invoices,
subscription-limit consumption, or a claim about unique text volume.

## Deduplicated surviving-log report

`run-token-overview.sh` installs the checksum-verified Token Use binary locally
under `.tools/`, asks it to import the surviving JSONL logs, and renders the
general overview and `year-YEAR` reports.

Token Use reads:

```text
~/.claude/projects/**/*.jsonl
~/.codex/sessions/**/rollout-*.jsonl
```

For Claude Code, Token Use deduplicates assistant records by message identity.
This avoids recounting messages copied into resumed or forked transcripts, but
it cannot recover sessions whose JSONL files have already disappeared. In the
2026 investigation, the stats cache retained 735 Claude sessions from May 3,
whereas surviving JSONLs provided 294 deduplicated sessions beginning July 17.

For Codex, Token Use derives usage from token-count events in rollout files.
Its result can differ from `threads.tokens_used`; the 2026 snapshot showed
approximately 2.49B parsed tokens versus approximately 2.79B retained thread
tokens. The LinkedIn report uses the latter because it matches the Codex
application headline, while the general report preserves Token Use's parsing.

## Reproduction

Run the complete pipeline for 2026:

```bash
./run-token-overview.sh 2026
```

Important outputs:

```text
results/linkedin-2026.html  social-ready, self-contained report
results/linkedin-2026.png   1200x1500 LinkedIn image
results/year-2026.html      deduplicated surviving-log report
results/year-2026.csv       exact monthly surviving-log values
results/year-2026.json      machine-readable surviving-log values
results/timings.tsv         wall-clock timings for pipeline stages
```

The generated outputs are a point-in-time snapshot. Rerunning the command can
change current-month values as active Claude Code and Codex sessions continue.
