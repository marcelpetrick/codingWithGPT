A case study on OCI containers as security boundaries in SDVs

Überblick und Zusammenfassungen:
The shift toward software defined vehicles (SDVs) is transforming automotive electronics into centralized high performance computing platforms. As software complexity and connectivity grow, strong isolation mechanisms and predictable execution environments become essential for cybersecurity. Although containerization is well established in IT and already used in
domains like infotainment, its application in other embedded automotive systems remains limited — despite its potential to manage complexity and strengthen security.

This talk presents lessons learned from a case study evaluating how OCI (Open Container Initiative) compliant containers can serve as secure execution boundaries for AUTOSAR Adaptive applications. We discuss practical insights into isolation behavior, integration challenges, and security hardening strategies observed during the study.

As a representative example, we examine a high-performance ECU integrating a Charging Control Unit (CCU) application, a function with substantial cybersecurity exposure. The CCU communicates not only with other in-vehicle applications but also with external charging stations.
Because charging interfaces such as ISO 15118, GB/T, and CHAdeMO are directly accessible from outside the vehicle, the CCU represents a major attack surface. If compromised, it could serve as a pivot point to target other ECUs in the network, making strong isolation
and tightly controlled communication pathways essential.

To mitigate this risk, the CCU Adaptive application is executed inside an OCI container that is used to establish a well-defined software security boundary. Container-level controls such as filesystem separation, Linux namespaces, POSIX capability reduction, cgroup limits, and seccomp filtering implement the software-level technical measures derived from the threat analysis and risk assessment (TARA). They complement platform protections like secure boot or secure diagnosis. The resulting container configuration becomes the enforceable definition of
the CCU’s isolation and communication constraints.

To avoid unnecessary overhead, a container-aware prototype Adaptive stack from Vector Informatik is used. It allows for execution and update management of containerized applications and for the shared use of Adaptive platform services by applications outside and inside of containers. The resulting architecture reduces integration complexity and supports
a structured, scalable approach to isolation in future SDV platforms.

The talk concludes with key findings, performance observations, and a discussion of how container-based isolation can evolve into a foundational cybersecurity mechanism for embedded automotive systems.

Art der Vermittlung:
Case study and explanation of methodolgy used

Nutzen:
The talk presents a new method of using containers in context of AUTOSAR Adaptive applications.
It shows that containers can provide isolation for critical AUTOSAR applications while avoiding
overhead of duplicating middleware components.
As an example, an ISO 15118 charging application is used. Due to the external interfaces to the
charging station, the charging application is a major attack vector. The talk illustrates how containers can be used to provide the necessary separations from the other AUTOSAR applications.
