Überblick und Zusammenfassungen:
The field of AI is evolving at a remarkable pace. LLMs are becoming increasingly capable with each generation, and the agent frameworks surrounding them — MCP, skills and tool use — are being developed just as quickly. Companies are adopting these technologies because they recognize the value of search and automation, and are customizing them to their specific development environments.

Embedded development is one area in which agents cannot work from source code alone. Hardware and software are tightly coupled and behaviour is state-driven, so an agent must understand how the target is configured, be able to control it and observe what actually happens on the hardware. This requires direct access to the running system, which only a capable debugger can provide. Without this access, an AI agent is limited to reasoning about code that it cannot run or inspect.

In embedded development, agentic debugging refers to a workflow in which an AI agent can observe and interact with a running program and the hardware on which it runs. This enables the agent to autonomously detect and investigate bugs by inspecting the runtime state, memory contents, peripheral interactions, logs and other execution artefacts, while forming and testing hypotheses about the root cause of a problem.

In this presentation, Lauterbach presents the current state of Agentic Debugging for embedded systems and shares lessons learned from practical deployments and experiments. We explore the opportunities and limitations of AI-driven debugging, the role of human oversight, and the challenges of integrating agents into existing development workflows. A short demonstration complements the discussion with a real-world example.

Art der Vermittlung:

Nutzen:
Discovering how to move beyond code-only AI assistants and unlocking the full potential of agentic debugging on real embedded hardware. Based on real deployments and hands-on experiments, the talk is giving attendees actionable ideas on how to integrate AI-powered debugging into existing development processes.
