The headline finding

The fastest model on the box is the one we rejected. cascade‑2 generates text 5.9× faster than the slowest model here — and took 2.3× longer to finish the same piece of work, because it fumbled its tools and had to retry: 84 steps where a good model needs 15. Vendor speed claims did not survive contact with a real task.

What we learned that we did not expect

Free performance

A software update re-ranked the entire field

Upgrading the server runtime — no new hardware, no new models — changed throughput by 0% to +221% depending on the model. It reshuffled which model was fastest and made our previous recommendation obsolete overnight.

nemotron +221% · north‑mini +60% · gemma4 +49% · control 0%
Reliability is pass/fail

Speed is a gradient. Tool use is not.

Models drive our tooling by emitting structured commands. Two failed badly: one dropped half of its parallel commands, and produced malformed instructions in 7 of 8 attempts. No throughput benchmark reveals this — only running the real workload does.

cascade‑2 — 7/10 gates · 50% and 87.5% failure rates
The requested model

Qwen3.8 is excellent, and wrong for this hardware

The release everyone asked for is genuinely smarter per word. But it reads all 27 billion parameters per token where our pick reads 3 billion — so on this memory-bound box it runs 4.3× slower. A bigger GPU would change the answer.

predicted 31.0 tok/s → measured 30.4 · within 2%
