Review skills compared

Built-in /code-review (Claude Code 2.1.302, default level = high) vs own /reviewBranch · tested on AlliumAssault · 8 runs · 2026-10-17

Verdict. Keep /reviewBranch as the default. Add /code-review as a second pass before an important merge. Cost is a tie. /code-review found more real defects (11 vs 5 unique), but less than half of what it reports is a real defect (47% vs 88%), so it fails the precision gate that was fixed before the runs. Neither skill reported a false finding. Both found the only medium-severity bug in every run.

5 · Good and bad, short

/reviewBranch

Good
  • Every finding holds up (88% real, 0 false).
  • Correct base branch on master/develop repos, stated up front.
  • Severity plus merge verdict: a decision, not a list.
  • Stable: you control the prompt.
Bad
  • Misses LOW docs/convention drift and UI slips.
  • Ignores uncommitted work.
  • About 25% more expensive per run; fills the main context.
  • Severity drifts between runs (f1: LOW vs MEDIUM).

/code-review

Good
  • Twice the unique real defects; a superset of RB's.
  • Checks conventions, reuse and efficiency too.
  • Many modes: fix, PR comments, ultra.
  • Cheaper per run and per real finding; isolated context.
Bad
  • Half the list is weak or pre-existing: triage cost moves to the human.
  • No verify pass at the default level; pads toward 5.
  • Weak base-branch logic for master repos.
  • No severity, no verdict; prompt can change under you.

6 · Limits of this test

  • One repository, two fixtures (both already merged and reviewed once), n = 2. Two runs show the spread, not a distribution.
  • Only the default level of /code-review (high). max adds verification and ultra is a cloud multi-agent review; both may change the precision result.
  • Headless mode. Interactive /code-review renders through ReportFindings; the findings should be the same.
  • "Real / weak" is one reviewer's call, but each call is written down with its evidence.
