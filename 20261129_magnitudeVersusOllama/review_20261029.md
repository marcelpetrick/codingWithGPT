# Review 2026-10-29: Magnitude versus Ollama, laptop round

Pedantic review of the code, the method and the documents at the end of the laptop round.
Every finding was checked against the files and the result rows. Status: fixed (with commit),
documented (a known limit, written into README/PLAN), or open.

| # | Area | Finding | Severity | Status |
|---|---|---|---|---|
| 1 | Code | `comparisons()` paired every Magnitude arm with every Ollama arm on a site, across model families (Gemma vs Qwen). | High | Fixed in `7f24f89` (pairs per family; e2e test with a second family). |
| 2 | Method | A 16-token warm-up does not show if an engine is stable. | Medium | Fixed in `9770f24` (warm up until two requests decode within 5%, max 5; recorded per row). |
| 3 | Method | The E4B A-4k rows were excluded as "kernel tuning"; the re-measurement disproved this (drafter off on that prompt). | Medium | Fixed in `ef68957`: the reason in `results/exclusions.jsonl` was rewritten to say so. This edits an append-only file; the edit is recorded here and in PLAN.md. |
| 4 | Method | The engines do not use the same GGUF files: Magnitude's catalog E4B/E2B are its own QAT-MTP repacks, Qwen 2B is unsloth's GGUF; Ollama uses its library tags. Same model and quant type, different files. | Medium | Documented (README "Where it ran", arm notes). Speed parity without drafters shows it does not move decode. |
| 5 | Method | Ollama runs with its defaults (flash attention off, f16 KV cache). A tuned Ollama could be faster. The vendor also compared defaults. | Medium | Documented. A tuned-Ollama arm is a candidate for the next round. |
| 6 | Method | Client-side prefill includes HTTP, template and scheduling time. For B-1k (about 90 prompt tokens) the prefill number mostly measures overhead. | Low | Documented in the `prefill` column note. The verdict uses decode only. |
| 7 | Method | GPU clock and temperature are not recorded. The arms ran one after the other, so thermal drift between arms is possible. | Low | Open. Within-cell ranges are tight (for example Qwen 2B B-8k 49.6–49.7 tok/s), which limits the effect. |
| 8 | Method | Magnitude's drafter use depends on the prompt (no drafting on one 3.2k-token prompt, little at 1.3k). The A workload has one prompt per context size, so A cells depend on that one prompt. | Medium | Documented in the verdict. B (5 prompts per cell) decides the verdict for this reason. |
| 9 | Code | The vision checker accepts a bare "3" for "third bar". An answer like "bars 1, 2, 3 and 4" would pass. | Low | Open. All answers were read: no such case in this round. |
